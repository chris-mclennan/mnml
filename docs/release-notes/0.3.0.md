# mnml 0.3.0

mnml 0.3.0 is a new mnml. It is written from scratch in Zig 0.16, as the
successor to the 0.2.x line in Rust, and it keeps what you used 0.2.x
for: the same editor, panes, keymaps and look, cell for cell, measured
against 0.2.21 row by row (`docs/PARITY.md`: 603 of 611 features done,
7 left out on purpose, 1 deferred). What changed is under the surface:
one static binary per platform with no runtime, every unit test and the
whole `.test` corpus run on a leak-checking allocator, and a config you
can read — ZON instead of TOML.

The repository is the same one, `chris-mclennan/mnml`. The Rust version
now lives, archived, at `chris-mclennan/mnml-rust`, with every 0.2.x
release and its binaries.

## Install

Prebuilt for macOS and Linux (x86_64 and aarch64) and Windows (x86_64).

- **macOS / Linux, the installer** — into `~/.local/bin`
  (`MNML_INSTALL_DIR` changes it):
  `curl --proto '=https' --tlsv1.2 -LsSf https://github.com/chris-mclennan/mnml/releases/latest/download/mnml-installer.sh | sh`
- **Homebrew** (macOS / Linux): `brew install chris-mclennan/tap/mnml`,
  or `brew upgrade mnml` from 0.2.x.
- **Windows, the installer** — into `%LOCALAPPDATA%\mnml\bin`, added to
  your user PATH:
  `powershell -ExecutionPolicy Bypass -c "irm https://github.com/chris-mclennan/mnml/releases/latest/download/mnml-installer.ps1 | iex"`
- **winget**: the `winget install` line in README (once the manifest PR
  is merged upstream).
- **Debian / Ubuntu, Fedora / RHEL**: the `.deb` and `.rpm` for each
  architecture are on this release.
- **By hand**: `mnml-<triple>.tar.xz` (`.zip` on Windows), each with a
  `.sha256`, and `sha256.sum` for the lot.
- **crates.io** is no longer a channel. `cargo install mnml-rs` installs
  0.2.22, the last Rust release, and stays there.

A [Nerd Font](https://www.nerdfonts.com/) is recommended; `--ascii`
works without one. Every archive carries mnml's own symbols font,
`share/mnml/fonts/MnmlSymbols.ttf`; nothing installs it into your font
directory behind your back, and mnml falls back for those few glyphs
until you do.

macOS and Linux run the whole test gate. Windows builds from the same
tree on every merge but has not been run end to end yet —
`docs/WINDOWS.md` keeps the honest list.

## Your config: run the converter first

0.3.0 reads `config.zon` and no TOML at all — not `config.toml`, not the
theme files, not `trusted_workspaces.toml`. The converter ships in the
last Rust release, because that is the build that still understands the
TOML:

1. **Before upgrading**, update to 0.2.22 and run
   `mnml export-config-zon`. It writes `~/.config/mnml/config.zon`
   beside your `config.toml`, which it leaves alone.
2. For each workspace with a `.mnml/config.toml`, run
   `mnml export-config-zon --out .mnml/config.zon` from inside it.
3. Upgrade.

Already upgraded? `cargo install mnml-rs --version 0.2.22 --root /tmp/mnml-022`
gets you the converter without touching your install, or download
0.2.22 from `chris-mclennan/mnml-rust`'s releases.

Every key the converter carries gets a comment from the schema's own
docs. Anything it cannot place lands in a trailing `// unmigrated:`
block at the end of the file, word for word, so nothing is dropped
silently.

If you forget, 0.3.0 tells you — once. The first launch that finds a
`config.toml` with no `config.zon` beside it shows a toast naming the
file and the command, and after that the same line is in `:messages` on
every launch. A workspace whose `.mnml/config.toml` has not been
converted shows `RESTRICTED` on the statusline until it is, because that
workspace's settings are not in effect.

**What does not come across:** the Rust-era integration sections. The
0.2.x integrations' own config and manifests
(`<data root>/integrations/*.toml`, `.mnml/integrations/*.toml`) are
never read by 0.3.0 and never deleted either; any integration keys in
`config.toml` end up in the `// unmigrated:` block. Set the new
integrations up from inside mnml (below). `docs/CONFIG.md` is the whole
commented `config.zon`.

## Integrations

0.3.0 starts the integrations over, on a new SDK and bridge. The mnml
download itself stays one binary; each integration is released on its
own and installed from inside mnml:

- **The Marketplace tab** (INTEGRATIONS section) lists the integrations
  built for your mnml version, from the index every mnml release
  carries (`integrations.json`). Installing one downloads it for your
  platform, checks its sha256 and sets it up. A newer version shows up
  as an update.
- **The first-launch wizard** has an Integrations section: tick Jira or
  Bitbucket and they are installed on the way out. Nothing is ticked by
  default.

**Jira and Bitbucket come first**, rewritten against their 0.2.x
counterparts: Jira Work, Fix Versions and Boards; Bitbucket's pull
requests and pipelines.

**The rest of the 0.2.x integrations are not in 0.3.0.** If you depend on
one of them, stay on 0.2.x for now — pin the version you have
(`brew pin mnml`, or install 0.2.22 from `chris-mclennan/mnml-rust`).
0.3.0 can still run any installed binary in a terminal pane with
`:term <binary>`; the old integrations' panes and chips do not load.

## Left out on purpose

From `docs/PARITY.md`'s Cuts table, each with the place 0.3.0 tells you:

- **Local, in-process completion model.** Ghost-text completion is
  API-only; a bundled model is a release-size and build-time cost this
  version does not carry. `ai.suggest_backend = local` shows a toast
  saying so.
- **brotli** response decoding in the HTTP client. It never asks for
  `br`; a server that sends it anyway gets a raw body and a toast.
- **WebP images.** PNG, JPEG and GIF render over kitty, iTerm2 and
  sixel; a `.webp` shows its `[image: alt]` placeholder.
- **The glyph builder's per-integration pane and live SVG preview.**
  mnml builds its own symbols font from SVG without FontForge, and the
  custom terminal and Claude glyphs rebake from your SVG; the builder
  pane is gone and its commands say why.
- **TOML, anywhere.** Config, themes, manifests and trust are all ZON.
- **The Rust integration binaries and their crates.io marketplace.** The
  crates stay published for 0.2.x users.
- **Sonos transport.** The `sonos.*` commands say why; the now-playing
  chip stays.
- **Playwright as the generic test runner.** `test.run_*` runs your
  project's own test command (cargo, npm, go, pytest); Playwright keeps
  its own commands and the Tests pane.

Deferred, not cut: **`--demo` launch mode**, until the website work.

## For users of the Rust version

- **Same repository, same name, same install channels** — Homebrew,
  winget and the installers move you to 0.3.0 on your next upgrade. The
  update toast in 0.2.x already points here.
- **Convert your config on 0.2.22 first** (above). 0.3.0 will not read
  the TOML, and it will not write over it either: going back to 0.2.x
  finds your `config.toml` where you left it.
- **Keymaps are two complete profiles**, vim (NvChad and Neovim chords)
  and standard (VS Code's), as in 0.2.x; the converter carries your
  `input_style` across.
- **Your 0.2.x integrations stay on 0.2.x** until each is rewritten.
  Jira and Bitbucket are here now.
- **Version 0.2.22 is the last Rust release.** Its source, issues
  history and binaries are at `chris-mclennan/mnml-rust`, read-only.
- **Asset names dropped the `-rs`**: `mnml-<triple>.tar.xz`, not
  `mnml-rs-<triple>.tar.xz`. Scripts that download a release by name
  need the new names.
- **`mnml --version`** prints the version and the profile it would run
  in.
- Found something 0.2.x did that 0.3.0 does not? `docs/PARITY.md` lists
  every feature row by row; if it is not there, file an issue on
  `chris-mclennan/mnml`.
